# 山河纪元 v2.5 全面优化报告

基于 UE5 架构、C++玩法、性能打包、UI/UMG、游戏设计、质量门禁六大方法论的全面优化。

## 一、架构层优化 (ue5-architecture)

### 1.1 模块依赖重构
- **Build.cs 优化**：区分 PublicDependencyModuleNames 和 PrivateDependencyModuleNames
- **新增模块**：GameplayTags（游戏标签系统）、RenderCore、RHI、Projects
- **禁用 Unity Build**：便于排查编译错误，每个文件独立编译
- **公共包含路径**：显式声明 Core/World/Character 目录

### 1.2 头文件包含策略
- 优先使用前向声明，减少头文件耦合
- 重型 include 移到 .cpp 文件
- 检测并消除循环依赖

### 1.3 命名规范统一
- UCLASS/USTRUCT/UENUM 仅在需要反射时使用
- 类型前缀：U(UObject)、A(Actor)、F(结构体)、E(枚举)
- 避免与引擎类型重名（已修复 NavigationSystem、FAmbientSound 等）

## 二、C++ 代码质量优化 (ue5-cpp-gameplay)

### 2.1 智能指针
- UPROPERTY 中的 UObject* 统一使用 TObjectPtr<>
- 减少裸指针使用，提高类型安全

### 2.2 空检查与安全
- 关键函数入口添加 IsValid() 检查
- GetWorld()、GetOwner() 返回值校验
- 数组访问边界检查

### 2.3 GameplayTags 集成
- 新增 FShanHeGameplayTags 标签库
- 状态/事件/阵营分类标签
- 替代硬编码 FName 比较

### 2.4 数据驱动配置
- 可调参数移到 DataAsset / DeveloperSettings
- 避免硬编码常量
- 支持运行时调整和 Mod

## 三、性能优化 (ue5-performance-packaging)

### 3.1 对象池系统
- Actor 对象池：频繁生成的 Actor（子弹、特效、NPC）复用
- UI Widget 池：菜单、提示、列表项复用
- 减少动态 Spawn/Destroy 开销

### 3.2 LOD 与细节层次
- NPC LOD：远距离降低 Tick 频率和骨骼更新
- 特效 LOD：远距离简化 Niagara 粒子数
- 音频 LOD：远距离降低音质和数量

### 3.3 流式加载
- World Partition 大地图分区加载
- 资源按区域懒加载
- 内存预算管理

### 3.4 帧率优化
- 帧率无关逻辑：所有时间相关计算乘以 DeltaTime
- Tick 频率控制：非关键系统降频更新
- 批量处理：数千 NPC 使用 MassEntity 或数据驱动

## 四、UI/UMG 优化 (ue5-ui-umg-slate)

### 4.1 生命周期管理
- NativeConstruct 中注册事件绑定
- NativeDestruct 中清理绑定和引用
- 避免重复创建/销毁导致的内存泄漏

### 4.2 数据绑定
- 单一数据源（Subsystem/Component）
- 事件驱动刷新，避免每帧轮询
- 显示 Widget 只读，不直接修改游戏状态

### 4.3 输入模式
- UI 打开时切换到 GameAndUI 或 UIOnly
- 关闭时恢复 GameOnly
- 显式管理键盘焦点

### 4.4 清理路径
- RemoveFromParent 后清除引用
- 定时器和委托在析构时取消
- 防止重复实例

## 五、质量门禁 (game-quality-gates)

### 5.1 单一清理入口
- 所有退出路径（死亡/通关/暂停/切场景）调用统一 Cleanup()
- 固定清理顺序：子对象 -> Buff/定时器 -> UI -> 投射物 -> 事件

### 5.2 定时器生命周期
- 所有 TimerHandle 跟踪并在清理时取消
- 避免悬挂定时器访问已销毁对象

### 5.3 帧率无关逻辑
- 移动/动画/衰减均使用 DeltaTime
- 物理使用固定时间步长

### 5.4 音频生命周期
- 场景切换时停止所有音频
- 后台暂停时静音
- 音频组件池化

### 5.5 存档版本化
- 存档包含版本号字段
- 支持版本迁移和向后兼容
- 仅持久化有意义的状态

## 六、游戏设计优化 (doubao-game-designer)

### 6.1 核心循环验证
- 三层玩法（战略/战斗/人生）信息差设计
- 玩家选择有意义且有后果
- 反馈循环及时且清晰

### 6.2 数值平衡
- 经济系统曲线验证
- 战斗数值可复算
- 成长节奏可控

### 6.3 系统闭合性
- 每个系统有明确的输入输出
- 系统间交互有定义
- 无悬空功能

## 七、视听优化 (seedance-20)

### 7.2 音频系统

### 7.3 特效系统
